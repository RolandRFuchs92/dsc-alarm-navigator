# Panel Guides Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static DSC menu map with a server-rendered Next.js app behind approved-only login, where panel content and step-by-step guides live in Postgres (shipped as tern migrations) and are shown on a keypad that looks like the user's own.

**Architecture:** A single Next.js App Router app sits at the repo root. Postgres schema and content are owned by tern SQL migrations, better-auth handles accounts, and drizzle is used for queries only. Keypad *behaviour* is a pure TypeScript reducer per panel family (`dsc-powerseries`). Keypad *looks* are React components, one per keypad model (PK5500, PK5508/16). Both are chosen by keys stored in the DB. Guide steps rebuild the expected keypad state by replaying keys from factory defaults.

**Tech Stack:** Next.js (App Router, TS), Node 24, npm, Postgres 16, tern v2, better-auth, drizzle-orm + pg, zod, vitest, @testing-library/react, Playwright (one smoke test), Docker.

**Spec:** `docs/superpowers/specs/2026-10-27-panel-guides-design.md`. Read it before starting any task.

**Reference material:**
- `src/data.js` and `src/app.js`: the app being ported. They are the behavioural oracle.
- `docs/reference/dsc-pc1864-v4.2-install-guide.pdf` (and `.txt`): DSC 29007359R003. This folder is gitignored.
- `/home/roland/playground/stedy/backend`: Roland's patterns for the tern wrapper, better-auth, drizzle and the Dockerfile.

## Global Constraints

- Node 24, npm 11, Postgres 16. TypeScript strict.
- tern is the **only** thing that changes the schema. Never use drizzle-kit push/migrate or better-auth's migrator.
- Migrations live in `migrations/NNN_name.sql` using tern's `---- create above / drop below ----` form. Every migration has a working down part.
- Migrations never run on container start. Roland runs `npm run db:migrate` by hand.
- No executable code is stored in the DB. Computed section labels use only the rule kinds `offset`, `block` and `grid`.
- Secrets come from env only: `DATABASE_URL`, `TEST_DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`. `.env.example` has keys with no values. Nothing secret goes in git or in the vault.
- Code style: `const result = …; return result;` at function ends. Every function name starts with one verb ("VANS"), e.g. `resolveRangeSection`, `selectDisplay`. Match the comment density of `src/app.js`.
- Mobile-first: works at 360px wide with a 16px side gutter and no horizontal scroll. Keep the existing look (Barlow, Barlow Condensed, Share Tech Mono, served through `next/font`).
- Guide key tokens: `0`–`9`, `*`, `#`, `<`, `>`, `{installer}`, `{master}`, separated by spaces. Nothing else is valid.
- Every page except `/login`, `/signup`, `/pending` and `/api/health` requires an approved session. Admin pages also need `isAdmin`.
- Unverified panel behaviour or data shows an "unverified" badge. It is never silently invented.
- **Git:** Roland commits only when he asks. Before Task 1, ask him once whether each task's commit step is pre-approved. If it isn't, skip the commit steps and leave the changes staged.

## Review Focus

1. **A user who is revoked while logged in on their phone.** Their next page load or server action must send them to `/pending`, even though their session is still valid. Test in Task 2.
2. **Sign-up requests that try to set `approved: true` or `isAdmin: true`.** The flags must be ignored and stay false. Test in Task 2.
3. **Unknown model slugs, out-of-range section numbers (`/map/999`), unknown guide slugs.** These must return a 404 page, not a 500. Tests in Tasks 10 and 11.
4. **`?step=` set to 0, past the end, or not a number.** The page should clamp to the first or last step and not crash. Test in Task 11.
5. **A stored guide whose key string the engine rejects.** This covers an invalid section, a token that doesn't belong, or a step that leaves the engine in an error flash. The guide lint test must fail and name the guide and step. Test in Task 11.
6. **A corrupt or old `localStorage` worksheet, or storage that is blocked.** The map must still render, using defaults. Test in Task 10.
