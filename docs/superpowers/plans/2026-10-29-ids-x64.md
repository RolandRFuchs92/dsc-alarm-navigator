# IDS X64 Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the IDS X64 with its Classic LED keypad: an X-Series engine, an on-screen keypad, a small location map, and two guides (change a user code, add zone 9 as Instant), without changing DSC behaviour.

**Architecture:** Shared types widen first (per-engine key sets, named status lights) with DSC behaviour pinned by the existing suite. Then catalog content in a tern migration, a pure reducer engine in `lib/engines/ids-xseries/`, a keypad face registered by `component_key`, and one migration per guide with a replay test.

**Tech Stack:** Next.js 16, TypeScript, Postgres 16 + tern, drizzle (reads), zod, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-29-ids-x64-design.md`

## Global Constraints

- Code style: `const result = …; return result;` at the end of functions that return a value; function names start with a verb.
- Engines are pure: no DOM, no storage; `pressKey` never mutates its input (tests freeze state).
- No inline `style` attributes (nonce CSP). Keypad styles go in `app/globals.css` beside the PK rules.
- Every location label, default and light behaviour cites the manual in a comment or the section's `description`: installer manual 700-398-02O (`docs/reference/ids-xseries-installer-manual.txt`), user manual 700-398-01J (`docs/reference/ids-xseries-user-manual.txt`).
- Defaults: installer code `9999`, master code `1234`, codes 4 digits (location 23).
- Guides ship `verified = false`. F, M, P are never guide tokens.
- User codes typed in user program mode, and the master code typed to enter it, never appear in `selectWorksheet`.
- DSC: every existing test stays green unchanged, except type-only edits that the type changes in Task 1 force.
- Tests need the test DB: `TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5435/dsc_test npm run db:migrate:test` then `TEST_DATABASE_URL=… npx vitest run`.
- Commit at the end of each task (local branch `feature/ids-x64`; never push).

## Rulings on the spec's open points

- **Status lights:** `Leds` becomes `Record<string, LedState>`. Each engine returns the lights its keypads have (DSC: ready/armed/trouble/ac; IDS: ready/armed/away/power) and each face decides which it draws and in what order. `LedState` gains `"alternate"` (flashing out of phase with other flashing lights) for user program entry, where ARM and READY alternate.
- **Long press on a computer keyboard:** the spec's Shift+`*` can't work, because `*` is already Shift+8 on most layouts. The keyboard instead mirrors the real keypad: on an engine whose keys include `hold*` / `hold9`, holding `*` or `9` for 1 s and releasing sends the hold key, and a shorter press sends the plain key on release. DSC keyboard handling is untouched.
- **Zone type 09:** Table 5 lists 09 "Instant Fire Zone (New)" but the valid-range line under Table 7 says `00 – 05, 08, 10 – 15`. The lookup includes 09 marked "newer firmware only", and the engine accepts 00–05 and 08–15.
- **201–208 default:** the manual doesn't give one. All zones default to off, the section is `verified = false`, and its description says to check the real panel. The guide only asserts that light 9 comes on.
- **After `[type] *` in star-advance:** the manual doesn't say whether the panel stays in the location or goes back to the top. The engine stays in the location and moves to the next zone, as with sub-locations (§8). The guide's `#` step notes: "If READY is already flashing with ARM and AWAY off, you are back at the top: skip this `#`."
- **201–208 status lights:** Table 26 and Figure 3 use READY/ARM/AWAY/POWER as the page marker. In partition allocation the marker light for the current page is on and the other three are off, and the display is `verified: false`.

## Review Focus

1. **The keyboard on the DSC map** must still send `<` `>` and all keys on press. Test: the DSC keyboard path doesn't change (Task 5).
2. **Keys the engine doesn't have** (`<` `>` pressed while on the IDS map, `mode` on a DSC keypad) must do nothing and must not throw. Test in Task 1 (host filter) and Task 3 (reducer ignores them).
3. **Wrong codes** (wrong installer code, wrong master code, an old code that doesn't exist, a duplicate or wrong-length new code) give the error beep, stay in the same prompt, and never change stored codes. Tests in Tasks 3 and 4.
4. **Codes never leave memory:** after any user-mode sequence, `selectWorksheet` contains no code and `localStorage` gets no code. Test in Task 4.
5. **Existing saved DSC worksheets and guides** still load: the existing suite runs unchanged in Task 1.
