# IDS X64 panel — design

_2026-10-29 · Roland + Claude · status: draft for approval_

## Why

Roland's friend has an **IDS X64** (IDS X-Series, South African brand) with the **Classic LED keypad**. Roland wants
the same experience the DSC side gives him: open the app at the panel, pick the IDS X64, pick a guide, and step
through it with an on-screen keypad that looks like the one on the wall and lights up the way it should at each step.

The first two jobs the friend needs: **change the user codes** and **add a new zone**.

## Goals

1. The IDS X64 appears in the device list next to the PC1864, with its own guides and a small location map.
2. An on-screen **Classic LED keypad** that looks like the real one (Figure 1 of the user manual).
3. A new **X-Series engine** that simulates installer programming and user (master) programming faithfully enough
   that every guide step shows the lights the friend should see.
4. Two guides, shipped as tern migrations, `verified = false`:
   - **Change a user code** (user program mode, option 1: old code → new code).
   - **Add a new zone**: zone 9 as an Instant zone (example until the real wiring is known).
5. The DSC side keeps working unchanged (all existing tests stay green).

## Non-goals

- A full map of every X64 location. Only the locations the guides use are added (decided by Roland). More come
  with later guides.
- The Curve LED, Curve LCD or Touch keypads. The engine and data must allow them later; only the Classic is built.
- The X8 and X16. Same family and engine, so later they're data, but only the X64 model is added now.
- Zone names, event log, Xwave wireless, aXess, reporting codes, outputs.

## Anti-goals

- **A simulator that invents panel behaviour.** Where the manual is vague, the step says so and the guide stays unverified.
- **A guide that presses F, M or P.** Holding those raises a real fire/medical/panic alarm. They are drawn on the keypad
  but are not valid guide tokens and do nothing on screen.
- **Breaking the DSC side**, including its stored guides and worksheets, while generalising shared types.

## Sources

Both PDFs come from idsprotect.co.za (IDS-hosted). Kept under `docs/reference/` (gitignored, like the DSC guide),
with `.txt` extracts for searching:

- **Installer manual** 700-398-02O: `IDS X-Series Installer Manual.pdf` — locations, zone types, programming procedure.
- **User manual** 700-398-01J (firmware 2.8x): `IDS X-Series User Manual.pdf` — keypads, LED tables, user program mode.

Every location label, default and LED behaviour in the migrations cites one of these (manual + section/table).

## Panel behaviour to simulate (from the manuals)

### Keys (Classic LED keypad)
`0`–`9`, `*` (enter / next), `#` (clear / back / exit), `MODE` (hex: MODE then 0–5 = A–F), `F`, `M`, `P`.
Some functions need a **long press**: hold `*` until the beep (user program mode), hold `9` (bypass).

### Lights
READY (green), ARMED (red), AWAY (red), POWER (red), and 16 amber zone lights (two columns: 1–8, 9–16).
In normal use zone lights show zone status. In programming they show values:
- **Small numbers / bitmaps:** light N on = value N, or option N on.
- **Data values:** binary-coded decimal: lights 1–4 = units (1,2,4,8), 5–8 = tens, 9–12 = hundreds, 13–16 = thousands
  (installer manual §6, Table 1).
- **Pages (locations 201–208):** 64 zones shown as 4 pages of 16; READY / ARM / AWAY / POWER mark page 1–4 (Table 26).

### Installer programming (installer manual §8)
- Enter: `#` installer-code `*` (default 9999). Long beep. **READY flashes.**
- Standard location: `[location] *` → READY on, AWAY flashes. Then `[data] *` (long beep, back to READY flashing,
  AWAY off) or `#` to leave it unchanged.
- Extended location with sub-locations: `[location] *` → READY on, ARM + AWAY flash. `[sub] *` → READY + ARM on,
  AWAY flashes. `[data] *` saves and returns to the sub-location prompt. `#` steps back a level.
- Zone types (locations 1–8, 8 zones each) can be entered three ways (§9, Location 1–8). Guides use the
  **star-advance** method: `[location] *`, each `*` moves one zone, `[type] *` sets the zone you're on.
- Bitmapped location: `[location] *` → READY on, AWAY flashes. `[number] *` toggles option/zone `number`
  (per the user manual's bitmap procedure; **the installer manual does not spell this out for 201–208 — unverified**).
  `*` on its own moves to the next page.
- `#` from the top of program mode exits (READY stops flashing).
- Invalid entry: error beep (3 short beeps).

### User (master) program mode (user manual §9)
- Panel disarmed. **Hold `*`** until the beep → ARM and READY flash alternately. Enter master code `*`
  (default 1234) → long beep, READY flashes.
- `[option] *` selects an option. Option 1 (edit a code): READY + ARM flash together → `[old code] *` →
  READY + AWAY flash, ARM on → `[new code] *` → back to READY + ARM flashing (ready for another old code).
- `#` exits the option, `#` again exits user program mode.
- Codes are 4 digits by default (location 23 can make them 6).

## Data (tern migrations)

Same catalog tables as the DSC (`002_catalog`), new rows:

- `manufacturer` IDS; `panel_family` X-Series, `engine_key = 'ids-xseries'`; `panel_model` X64
  (installer default 9999, master default 1234, `source_doc` = the installer manual).
- `keypad_model` Classic LED: `component_key = 'ids-classic-led'`, `display_type = 'lights'`, `light_count = 16`,
  default (and only) keypad for the X64.
- Locations as `section` rows (`num` = location number), only those the guides touch:
  - 1–8 Zone types (8 zones each; zone 1 = 01, 2 = 02, 3–8 = 04; 9–64 = 00 Disabled; Table 5/6).
  - 101–164 Zone properties (bitmap, Table 23; option 6 "zone bypassing" ON by default).
  - 201–208 Partition zone allocation (bitmap, 64 zones on 4 pages; default zones 1–8 on partition 1 — **check
    the manual; if it doesn't say, the builder marks the default unverified**).
  - 197 Installer code, 23 code length (context for the guides; read-only use).
- A `lookup` for zone types (Table 5: 00–05, 08–15).
- The existing schema's `kind` CHECK (`data | toggle | sub | phone | action | module`) is the builder's to extend or
  reuse; the jsonb shapes stay validated by zod.
- User program options 0–5 are `keypad_command` rows in the content migration (labels cite user manual §9), like the
  DSC's [*] commands, so they show in the map's command list. They are not installer sections. _(Claude's call.)_
- Zone 9 needs the plug-in zone expander (P/N 860-06-X-08PI, installer manual §2); the guide says so.

## Code

### Shared types become panel-neutral
Today `Key` and `Leds` are DSC-shaped (`< >`, ready/armed/trouble/ac). They must widen without changing DSC behaviour:
- **Keys:** each engine declares its own key set. X-Series adds `mode`, `f`, `m`, `p`, and long-press keys
  `hold*`, `hold9`. Guide lint checks a guide's tokens against **its panel's** key set, so DSC guides can't use
  `mode` and IDS guides can't use `<`.
- **Status lights:** a keypad gets a list of named lights (name, colour, state) from the engine instead of the
  fixed four, so the IDS keypad can show READY / ARMED / AWAY / POWER.

### Engine `lib/engines/ids-xseries/`
Pure reducer like `dsc-powerseries/`: state, reducer, selectors. Modes at minimum: idle, installer-code entry,
program top, location (standard / bitmap with page / star-advance zone list), user-code entry (after hold `*`),
user program top, option 1 old-code, option 1 new-code. Selectors produce the 16 zone lights (status, value in BCD,
or bitmap page) and the four status lights per the tables above. Map navigation methods are optional
(the `PanelEngine` contract already allows that); the map page must at least render the X64 locations and let the
keypad be pressed.

### User codes are never stored _(Claude's call)_
The DSC worksheet saves typed values to localStorage. For the X-Series, codes typed in user program mode (and the
master code typed to get in) live only in the engine's in-memory state and are **never** returned by
`selectWorksheet`, so real codes typed on the map page are not saved in the browser. The replay test for the user-code
guide checks modes and lights, not stored codes.

### Long press _(Claude's call)_
On the IDS Classic face only, holding `*` or `9` for one second sends `hold*` / `hold9` (with a visible "held" state);
a shorter press sends `*` / `9` on release. DSC faces keep firing on press, unchanged. Keyboard: Shift+`*` / Shift+`9`
send the hold keys. This mirrors the real keypad and lets the map page enter user program mode and bypass.

### Keypad component `components/keypads/IdsClassicLed.tsx`
Classic layout: dark left panel (status lights top, X-SERIES label, two columns of 8 zone lights), 3×4 keys,
bottom row MODE (narrow), F, M, P. CSS modules only (CSP). F/M/P are inert in the simulator.

### Guide keys
- New tokens: `mode`, `hold*`, `hold9`. F/M/P are **not** guide tokens.
- New code placeholders, shown as labelled keycaps like `{installer}`:
  - `{user-code}` "the code to change" — replays as the master default (1234) so the example changes the master code.
  - `{new-code}` "the new code" — replays as an example (e.g. 4321).
- DSC token rules are unchanged.

## Guides

Both `verified = false`, one migration each, with a replay test like the DSC guides.

**1. Change a user code** (user program mode, option 1)
1. Make sure the system is disarmed.
2. `hold*` — ARM and READY flash alternately.
3. `{master} *` — long beep, READY flashes.
4. `1 *` — option 1, READY + ARM flash together.
5. `{user-code} *` — READY + AWAY flash, ARM on. Note: to change the master code itself, enter the master code here.
6. `{new-code} *` — back to READY + ARM flashing; repeat 5–6 for more codes.
7. `# #` — leave the option, then user program mode.
Notes cover: the new code must be unique; codes are 4 digits unless location 23 says 6; if the old code is unknown,
option 5 shows a code's slot and option 3 sets a code by slot (described, not stepped).

**2. Add a new zone** (zone 9, Instant; installer mode)
1. `#` `{installer}` `*` — READY flashes.
2. `2 *` — location 2 = zones 9–16; on zone 9.
3. `4 *` — zone 9 = 04 Instant.
4. `#` — back to program top.
5. `2 0 1 *` — partition 1 allocation, page 1 (zones 1–16; READY marks the page).
6. `9 *` — toggles zone 9 on (light 9 comes on). **Unverified toggle method; the step says so.**
7. `#` — back to program top.
8. `1 0 9 *` — zone 9 properties: check, change nothing (bypassing is on by default). `#`.
9. `#` — leave installer programming.
Warnings: zone 9 needs a zone expander fitted and enrolled; type 04 sounds immediately when armed.

## Testing

- Engine unit tests per mode and per LED table row used, citing the manual table.
- Replay tests for both guides (state after each step: mode, lights, stored values).
- Guide lint stays global: every guide replays through its own engine with its own key set.
- Keypad component render test (lights, keys present, F/M/P inert).
- Full existing suite green; Playwright smoke opens the X64 guide page with zero CSP violations.
